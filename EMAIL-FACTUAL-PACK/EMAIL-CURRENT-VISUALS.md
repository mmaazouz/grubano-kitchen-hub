Screenshots `current-renders/png/<ID>@600.png` (desktop-ish, 600 px) and `<ID>@390.png` (mobile) taken with headless Chrome on a white ground with 16 px padding. **Images-off variant: not applicable — zero `<img>` in every template** (verified by the harness: `hasImages=false` ×60). Gallery: `current-gallery.html` (open locally; PNG thumbnails + subject + links to the raw fragment). These are fossils for CURRENT-STATE reference only. Never send them.

## Observations that hold for every render
- Fragment without `<html>/<head>/<body>`, no `lang`, no doctype, no preheader, no `<title>` → the client decides the document defaults.
- Width: `max-width:480px` (rail, inline, claims, nudges) · `520px` / `560px` (admin alerts) · `100%` table (supplier PO).
- Typography: `Inter,Arial,sans-serif` requested but Inter is never embedded → Arial/Helvetica in practice; admin alerts `system-ui,Arial`.
- Colour: heading `#F97316` (legacy brand orange, **not** the gb-foundation `--gb-zest #FF6A1F`), text `#1a1a2e` (legacy navy, not `--gb-ink #0F2742`), muted `#6b7280` / `#9ca3af`, button `background:#F97316;color:#fff;border-radius:12px`. Status is conveyed by heading text + "✓" glyph + orange colour only (no semantic colour system, no icons).
- Buttons are styled `<a>` (no VML) — Outlook desktop renders them as plain links with background only where supported. Long styles with embedded newlines inside `<a>` (rail buttons) — the magic-link route explicitly avoids this after a "non-clickable blob" bug.
- No logo, no header band, no footer identity beyond one sentence; no unsubscribe except the nudge family; no physical address / legal mention anywhere.
- RTL: only claim + nudge shells set `dir="rtl"` for `ar` (see `CLAIM_RECEIVED__ar`).
- Contrast: body `#1a1a2e` on white ≫ AA; muted `#6b7280` 13 px ≈ 4.8:1 (AA); footer `#9ca3af` 12 px ≈ 2.9:1 (**fails AA**); orange `#F97316` on white ≈ 2.8:1 (**fails AA for the 13–20 px heading and for white-on-orange button text**).
